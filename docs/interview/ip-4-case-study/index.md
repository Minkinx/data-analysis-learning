# IP 4. Case Study

> Case Study 是数据分析面试中最能体现候选人思维深度和结构化的环节，通常在业务面中占据核心地位。本章提供分析框架 + 典型案例，帮助你建立系统的 Case Study 方法论。

## 五大类型

| 类型 | 核心能力 | 适用级别 | 题目示例 |
|------|----------|----------|----------|
| [指标异动分析](./01-metric-anomaly) | 归因分析、假设驱动 | 初中级 | DAU 下降 10% 如何分析 |
| [业务策略评估](./02-strategy-evaluation) | 因果推断、实验设计 | 中高级 | 补贴活动效果评估 |
| [产品分析](./03-product-analysis) | 产品思维、用户洞察 | 中高级 | 新功能采用率分析 |
| [费米估算](./04-fermi-estimation) | 逻辑拆解、数量级估算 | 所有级别 | 估算北京有多少加油站 |
| [分析思路题](./05-analytical-thinking) | 框架构建、假设验证 | 中高级 | 如何分析用户流失原因 |

## 通用分析框架（五步法）

```
1. 澄清问题 (Clarify)
   - 确认指标定义、时间范围、业务场景
   - 对齐预期：到底是什么问题？

2. 拆解框架 (Framework)
   - 按维度拆解（时间/地区/用户群/渠道）
   - 按公式拆解（漏斗分解/加法分解/乘法分解）
   - 按业务流程拆解

3. 数据验证 (Analyze)
   - 锁定主要矛盾维度
   - 关联分析找原因
   - 排除法验证假设

4. 得出结论 (Conclude)
   - 根因总结（是什么、为什么）
   - 量化影响程度

5. 行动建议 (Action)
   - 短期止血措施
   - 长期解决方案
   - 后续验证计划
```

## 面试评分维度

| 维度 | 权重 | 考察重点 |
|------|------|----------|
| 结构化思维 | 30% | 是否有框架、逻辑是否清晰 |
| 业务理解 | 25% | 对业务场景和指标的理解深度 |
| 量化分析 | 25% | 是否用数据说话、能否做估算 |
| 表达沟通 | 20% | 是否清晰、有条理、有亮点 |

## 练习建议

1. **先背框架再灵活运用**：五步法是基础，但不要生搬硬套
2. **多积累业务场景**：不同行业（电商/内容/金融/本地生活）的分析逻辑有差异
3. **动笔/动口练习**：对着录音讲一遍，看自己是否逻辑自洽
4. **准备反问**：面试结束前的反问环节也是加分项，准备 2-3 个有深度的问题
