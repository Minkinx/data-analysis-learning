# IP 5. Product Sense

> Product Sense（产品感）面试题主要考察候选人能否从数据角度理解产品、定义指标、设计数据产品，以及用数据驱动业务决策。这类题目在中高级岗位面试中占比很高，尤其在外企和产品驱动型公司。

## 核心能力矩阵

| 能力维度 | 考察点 | 典型问题 |
|----------|--------|----------|
| 指标定义 | 能清晰定义核心指标，理解指标间的关系 | "如何定义用户活跃？" |
| 指标体系 | 能搭建系统化的指标框架 | "对一个电商平台，你会关注哪些指标？" |
| 数据产品设计 | 能设计可落地的数据工具 | "设计一个业务监控看板" |
| 数据驱动决策 | 能用数据给出有洞察的建议 | "数据告诉你什么？你会怎么做？" |

### 题目 1：如何定义"用户活跃度"？

**问题**：对于一个内容社区产品，如何定义用户活跃度？请给出你的指标体系。

**解答框架**：

**第一步：明确语境**

不同类型的"活跃"定义不同：
- 轻度活跃：只要打开 App 就算
- 中度活跃：有阅读/浏览行为
- 重度活跃：有互动/创作行为

建议采用**分层定义**：

```
用户活跃度分层：

DAU (日活跃用户)：当天打开 App 的用户
WAU (周活跃用户)：最近 7 天内打开过 >= 3 天的用户
MAU (月活跃用户)：最近 30 天内有登录行为的用户

高质量活跃用户（核心指标）：
- 当天有 >= 3 次内容消费
- 且至少发生 1 次互动（点赞/评论/分享）
```

**第二步：指标体系**

| 指标类别 | 具体指标 | 解释 |
|----------|----------|------|
| 规模指标 | DAU、WAU、MAU | 活跃用户总量 |
| 质量指标 | 人均使用时长、人均阅读篇数、互动率 | 活跃的质量 |
| 结构指标 | 新用户占比、老用户占比、各层级用户比例 | 活跃的结构健康度 |
| 粘性指标 | DAU/MAU、用户月活跃天数 | 用户粘性 |

**第三步：维度扩展**

活跃定义也需要考虑：
- 时间维度：工作日 vs 周末、工作日白天 vs 晚上
- 用户细分：新用户（注册 < 7 天）vs 老用户
- 场景维度：通勤场景 vs 居家场景

**第四步：常见陷阱**

- ❌ 只关注 DAU，忽略活跃质量
- ❌ 将"打开 App"等同于"有效活跃"（可能只是后台唤醒）
- ❌ 定义过宽，所有用户都是"活跃"导致指标失效
- ❌ 定义过窄，忽略了轻度用户的价值（他们是未来的种子用户）

### 题目 2：为你的产品设计指标体系

**问题**：假设你是一个电商平台（如淘宝）的数据分析师，你会设计一套什么样的指标体系来全面监控业务健康度？

**解答框架**：

**AARRR 模型框架**：

| 阶段 | 指标 | 定义 | 关注点 |
|------|------|------|--------|
| Acquisition | 新增用户数、获客成本 (CAC)、渠道来源分布 | 新用户从哪里来 | 渠道效率 |
| Activation | 首单转化率、首单时长 | 用户是否体验到核心价值 | 引导效率 |
| Retention | 次日/7日/30日留存、复购率 | 用户是否回来 | 产品价值 |
| Revenue | GMV、ARPU、LTV、客单价 | 用户贡献了多少价值 | 商业模式 |
| Referral | 分享率、邀请转化率、K 因子 | 用户是否推荐给他人 | 增长飞轮 |

**分层指标体系**：

```python
# 电商指标体系的 Python 表示
ecommerce_metrics = {
    '流量层': {
        'UV': '独立访客数',
        'PV': '页面浏览量',
        'session_duration': '平均访问时长'
    },
    '转化层': {
        'add_cart_rate': '加购率',
        'order_rate': '下单转化率',
        'payment_rate': '支付转化率',
        'payment_success_rate': '支付成功率'
    },
    '交易层': {
        'GMV': '商品交易总额',
        'order_count': '订单总数',
        'avg_order_value': '平均客单价',
        'refund_rate': '退款率'
    },
    '用户层': {
        'new_user_ratio': '新用户占比',
        'repeat_purchase_rate': '复购率',
        'high_value_user_ratio': '高价值用户占比'
    },
    '商品层': {
        'sku_count': '在售 SKU 数',
        'out_of_stock_rate': '缺货率',
        'category_penetration': '品类渗透率'
    }
}
```

**面试亮点**：

在基础指标体系之上，提出**北极星指标**的建议：
- 电商平台北极星指标通常为 **GMV** 或 **有效订单量**
- 辅助北极星：**NPS（净推荐值）** 或 **复购率**（衡量长期健康度）

### 题目 3：设计一个业务监控看板

**问题**：业务方需要一张"日常业务监控看板"，请你设计。

**解答框架**：

**第一层：核心指标卡（一眼看清现状）**

```
+------------------------------------------------------+
|  📊 今日概览 (截至 10:00)                              |
|  DAU: 520 万  ▲ 3.2%  vs 昨日  |  GMV: 2.3亿  ▼ 1.5% |
|  订单量: 18.5 万  ▲ 0.8%  vs 昨日  |  转化率: 4.2%  ▼ 0.3pp |
+------------------------------------------------------+
```

设计要点：
- 左上角：最重要的北极星指标
- 每个指标附带环比变化（绿色上升，红色下降）
- 与目标值的差距（达成率）

**第二层：趋势图表（看变化趋势）**

```
+--------------------------------------------------+
|  DAU 近 30 天趋势                                  |
|  ╱╲ ╱╲  ╱╲ ╱╲                                    |
| ╱  ╲╱  ╲╱  ╲╱  ╲╱  ╲                             |
|  上周同期 ----   本周 ----   目标 ----              |
|  [切换：7日/30日/90日]                             |
+--------------------------------------------------+
```

设计要点：
- 核心指标的时序趋势图
- 包含历史对比（同比/环比/目标线）
- 支持时间粒度切换（日/周/月）

**第三层：下钻分析（找原因）**

```
+----------+----------+----------+------------------+
| 渠道     | DAU      | 变化     | 趋势             |
|----------|----------|----------|------------------|

+----------+----------+----------+------------------+

设计要点：
- 维度切换：可按渠道、地区、用户群等维度下钻
- 异常维度用颜色标识（红/黄/绿）
- 支持一键下钻到明细数据

**第四层：告警与异常事件列表**

```

**面试加分项**：

- 可交互性：支持筛选、下钻、导出

### 题目 4：数据产品设计 — 实验平台

**问题**：设计一个 A/B 实验平台，支持产品和运营团队自助做实验。

**解答框架**：

**核心功能模块**：

```
实验平台 = 实验设计 + 流量管理 + 数据监控 + 结果分析
```

**模块 1：实验设计**
```
- 实验名称、描述、创建人
- 假设描述（H0 / H1）
- 实验类型（UI 实验 / 算法实验 / 运营策略实验）
- 核心指标选择（从指标库选取）
- 样本量计算器（输入 MDE、α、β，输出所需样本量）
- 实验周期建议
```

**模块 2：流量管理**
```
- 分流方式：用户 ID Hash / 设备 ID / Cookie
- 分层互斥策略：
  Layer 1: UI 实验（互斥）
  Layer 2: 算法实验（互斥）
  Layer 3: 运营实验（正交）
- 流量分配：对照组 X% / 实验组 Y%
- 流量过滤器：地区 / 平台 / 用户群
```

**模块 3：数据监控 (实时)**
```
- 核心指标实时趋势图
- 样本量追踪
- 分流均衡性检查（AA 检验）
- 潜在风险告警（负面指标异常）
- "假装死"按钮（紧急停止实验）
```

**模块 4：结果分析**
```
- 核心指标统计检验（Z 检验 / t 检验）
- 置信区间展示
- 分层分析 / 子群分析
- 多重比较校正（Bonferroni / FDR）
- 实验结果报告导出（PDF）
```

**面试加分项**：

1. **SRM (Sample Ratio Mismatch) 检测**：自动校验分流比例是否符合预期
2. **Novelty Effect 检测**：按时间分段看效果是否衰减
3. **长期效果跟踪**：实验结束后自动追踪 14 天/30 天效果
4. **MDE 敏感性分析**：用历史数据告诉用户"你的实验需要 XX 天才能达到统计功效"

### 题目 5：数据驱动决策案例

**问题**：基于数据，你会给业务方什么建议？请结合一个真实场景说明。

**场景**：你是某电商平台的数据分析师，发现以下现象：
1. **新用户首单转化率**：30%，行业平均 40%
2. **新用户注册后 7 天内复购率**：10%，行业平均 20%
3. **从注册到首单的平均时间**：3 天，竞品 1 天
4. **首单用户和非首单用户的次日留存**：60% vs 15%

**分析过程**：

**Step 1: 明确问题核心**

数据说明：**首单转化是用户留存的 key moment**。首单用户次日留存 60% vs 非首单 15%。

核心问题 = 如何提升新用户首单转化率（从 30% 到行业平均 40%）。

**Step 2: 原因诊断**

新用户从注册到首单的路径：
```
注册 → 浏览商品 → 加购 → 下单 → 支付
30%   →   48%    →  35%  →  80%  →  90%
```

最大流失点在"浏览→加购"（48% → 35%，流失绝对值最大）。

进一步分析为什么加了购物车但不结算：

| 原因 | 占比 | 数据来源 |
|------|------|----------|
| 还在比价/犹豫 | 35% | 用户行为：加购后浏览了竞品 |
| 运费门槛 | 25% | 结算时放弃，凑单失败 |
| 注册流程问题 | 15% | 注册后未绑定支付方式 |
| 商品评价不好 | 10% | 看了差评后退缩 |
| 其他 | 15% | — |

**Step 3: 建议方案**

基于数据提出 3 条有优先级建议：

1. **新用户专享包邮（P0）**
   - 数据支撑：25% 因运费放弃，新用户客单价低更难凑单
   - 预期效果：加购→支付转化提升 5-8pp

2. **首单任务引导（P1）**
   - 数据支撑：注册到首单平均 3 天，说明用户不知道买什么
   - 方案：新用户注册后推荐新手专区、热门商品
   - 预期效果：注册→首单时间缩短到 1 天

3. **首单优惠券策略优化（P2）**
   - 数据支撑：35% 在比价
   - 方案：加入购物车 30 分钟后发限量优惠券
   - 预期效果：放弃购物车挽回率提升 10%

**Step 4: 量化预期**

```python
# 预估效果
current_state = {
    'new_users_per_day': 10000,
    'first_order_rate': 0.30,
    'daily_first_orders': 3000,
    'avg_order_value': 80,
    'daily_new_user_gmv': 240000
}

after_optimization = {
    'first_order_rate': 0.38,  # 提升 8pp
    'daily_first_orders': 3800,
    'daily_new_user_gmv': 304000
}

daily_gmv_increase = 304000 - 240000  # +64000
monthly_gmv_increase = daily_gmv_increase * 30  # +192万
```

**Step 5: 衡量标准**

```
成功标准（上线后 2 周评估）：
- 首单转化率从 30% → 38%（提升 8pp，里程碑值 35%）
- 注册→首单时间从 3 天 → 2 天以内
- 首单用户 7 日留存维持 60% 或更高（不能为了转化牺牲留存）
- 补贴成本 vs 增量 GMV 的 ROI > 3
```

**面试加分项**：

- 提出 A/B 测试验证方案（避免一次性全量上线风险）
- 考虑长短期平衡（补贴来的用户 vs 自然转化的用户，质量是否一致）
- 关注漏斗中所有环节的动态平衡（不能只优化一个环节导致其他环节出问题）

### 题目 6： 如何衡量用户体验？

**问题**：如何用数据量化用户体验？请给出一个可执行的框架。

**解答框架**：

**多维度用户体验指标体系**：

```python
ux_metrics = {
    '性能体验': {
        'app_launch_time': 'App 冷启动时间',
        'page_load_time': '页面加载时间',
        'api_response_time': 'API 响应时间',
        'crash_rate': '崩溃率',
        'ANR_rate': '无响应率'
    },
    '功能体验': {
        'task_success_rate': '任务完成率',
        'task_completion_time': '任务完成时长',
        'error_rate': '操作错误率',
        'feature_usage_depth': '功能使用深度'
    },
    '内容体验': {
        'content_relevance_score': '内容相关度评分',
        'recommendation_ctr': '推荐点击率',
        'bounce_rate': '跳出率',
        'session_length': '单次访问时长'
    },
    '主观体验': {
        'NPS': '净推荐值',
        'CSAT': '客户满意度评分',
        'CES': '客户费力度',
        'survey_response_rate': '调研回复率'
    }
}
```

**关键方法论**：

1. **客观指标 + 主观指标结合**：性能数据 + 调研数据
2. **基准线 + 目标值 + 告警阈值**：建立正常的波动范围
3. **分群对比**：不同用户群的体验差异（新用户 vs 老用户、不同机型）
4. **竞品对标**：与行业基准对比（如加载时间行业基准 2s）

**面试亮点**：

提出 **HEART 框架**（Google 的用户体验度量框架）：
- H (Happiness)：用户满意度（NPS、CSAT）
- E (Engagement)：参与度（DAU、使用时长、使用频次）
- A (Adoption)：采用率（新用户注册、功能使用率）
- R (Retention)：留存率（次日/7日/30日留存）
- T (Task Success)：任务完成率（核心路径完成率）

建议实际工作中根据产品类型裁剪 HEART 框架。
