Dashboard 设计 ​

Dashboard（仪表板）是数据分析的终端输出，所有数据清洗、建模、计算工作最终都要通过仪表板呈现在决策者面前。好的仪表板让信息一目了然，差的仪表板让用户迷失在数据中。

信息层级（Information Hierarchy） ​

Dashboard 的设计遵循 F 型扫描模式（F-pattern）或 Z 型扫描模式（Z-pattern），读者视线从左上向右下移动。因此，信息重要度从左到右、从上到下递减。

三层层级结构 ​

┌────────────────────────────────────────────┐
│  █████████████ 顶部导航栏 / 筛选器 █████████  │
│  ══════════════════════════════════════════ │
│  ▊ 关键 KPI 行    ▊       ▊       ▊        │
│  ▊ 总营收 2.3B    ▊ 毛利 45% ▊ 客户数 1.2M  │
│  ▊ YoY +12.3%    ▊ +2.1%   ▊ +8.7%         │
│  ══════════════════════════════════════════ │
│  ┌──────────┐ ┌───────────────────────────┐ │
│  │ 主图表     │ │ 辅助分析面板              │ │
│  │ (核心指标  │ │ (明细表 / 下钻详情)       │ │
│  │  趋势图)   │ │                          │ │
│  └──────────┘ └───────────────────────────┘ │
└────────────────────────────────────────────┘

第一层 — 概览层（Executive Summary）：3-6 个核心 KPI，展示业务健康度的整体状态。通常在最上方一行。

第二层 — 分析层（Analytical Layer）：核心图表和趋势，回答"发生了什么"和"趋势如何"。占据 60% 以上的面积。

第三层 — 明细层（Detail Layer）：详细数据表格、下钻详情、原始记录，供需要深入调查的用户使用。

设计原则

Dashboard 的设计目标是让用户在 5 秒内 理解当前的业务状态（概览层）， 30 秒内 发现关键趋势或异常（分析层）， 5 分钟内 找到原因（明细层/交互下钻）。

KPI 布局规则 ​

单值 KPI 卡片 ​

每个 KPI 卡片应包含以下核心信息：

┌─────────────────────────────┐
│ 客户获取成本 (CAC)          │  ← 指标名称
│                ¥ 328         │  ← 当前值（大字号）
│  ¥ ▲  5.2%  vs 上月          │  ← 变化方向和幅度
│       目标值 ¥ 350   ✓       │  ← 目标达成状态
└─────────────────────────────┘

布局规范：

  • 指标名称在上方，用小字号（次级信息）
  • 当前值居中，用大字号（首要信息）
  • 变化方向和目标对比在下方，用更小字号
  • 使用颜色语义：红色 = 恶化，绿色 = 改善（或反向，根据业务而定）

KPI 组织方式 ​

  • 按主题分组：营收相关放一起，客户相关放一起
  • 按因果关系：领先指标（Leading Indicators）在前，滞后指标（Lagging Indicators）在后
  • 按频率分组：实时指标与日报指标分开展示

执行型 vs 运营型 Dashboard ​

两种 Dashboard 的设计逻辑有本质区别，不能混为一谈。

维度执行型（Executive）运营型（Operational）
目标用户C-level, VP, 总监一线分析师、运营人员
核心问题"业务健康度如何？""下一步该做什么？"
刷新频率每日/每周实时/每小时
交互深度被动浏览，少交互主动分析，深度交互
图表数量5-8 个10-20 个
设计风格简洁、大气、空间充足信息密度高，工具化
数据粒度聚合级（月度/周度）明细级（日度/实时）
异常处理标记异常，引导下钻实时告警，直接触发行动

执行型 Dashboard 最佳实践 ​

  • 先给结论：每个图表的上方用一句话总结核心洞察
  • 少即是多：屏幕上的每一个元素都要问自己"如果去掉它，决策者会漏掉什么？"
  • 对比是核心：把实际值与目标值、上月、去年同期的对比放在显眼位置
  • KPI 数量限制：不超过 7±2 个核心指标（Miller's Law）

运营型 Dashboard 最佳实践 ​

  • 可操作性：每个指标都应该有对应的操作路径
  • 实时反馈：数据更新后立即反映在界面上
  • 告警机制：设定阈值，触发后自动标注/通知
  • 导出功能：支持导出原始数据做进一步分析

交互设计（Interaction Design） ​

下钻（Drill-Down） ​

用户点击某个数据元素后，进入更细粒度的视图。

text
下钻层级设计示例：
  年度营收（全国总览）
   → 季度营收（按区域）
    → 月度营收（按省份）
     → 日报营收（按城市/门店）

实现要点：

  • 每次下钻都显示当前路径（Breadcrumb），支持一键返回
  • 下钻后保留上下文，不要完全切换页面
  • 提供"返回上层"和"重置"按钮

筛选与参数控制（Filtering） ​

合理的筛选设计是 Dashboard 可用性的关键：

  • 全局筛选器（Global Filter）：影响整个 Dashboard，放在顶部
  • 上下文筛选（Contextual Filter）：只影响特定图表，放在图表附近
  • 联动筛选（Cross-Filtering）：点击一个图表的数据点，其他图表联动更新

交叉筛选（Cross-Filtering / Brushing） ​

用户选中某个图表中的部分数据，其他图表同步高亮同一维度。

text
用户点击 "华东" 区域 →
  营收趋势图：只高亮华东曲线
  区域占比图：高亮华东对应的扇形
  客户分布图：只显示华东城市
  明细表：筛选出华东的交易记录

设计原则：

  • 被选中的状态要清晰可辨（颜色变化 + 高亮）
  • 提供一键清除所有筛选
  • 显示当前处于筛选状态中的维度数量和占比

悬停提示（Tooltip） ​

Tooltip 是提供额外信息的重要手段，但不应承载关键信息。

好的 Tooltip 设计：

  • 显示精确数值（图表中无法显示的精度）
  • 提示数据的定义或来源（如"销售额 = 含税金额"）
  • 显示样本量（n=xxx），帮助判断可靠性
  • 不超过 3-4 行信息

性能与加载策略 ​

  • 按需加载：初始只加载概览层数据，分析层和明细层在用户滚动或点击时加载
  • 数据缓存：相同时间粒度的查询结果缓存到内存
  • 限制数据量：前端展示的数据点不应超过 1000 个，超过则做聚合采样
  • 渐进式加载：先显示骨架屏（Skeleton Screen），再填充数据
